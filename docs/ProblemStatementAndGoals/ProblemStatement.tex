\subsection{Problem}

\wss{What problem are you trying to solve?  Why is it important? Do not talk
about how you will solve the problem, only what the problem is.  AI is rarely
part of the problem.  The problem is ``what'' you want to do, not ``how'' you
want to do it.  The problem statement should be written in a way that is
understandable to a non-technical audience.}

We want to streamline the capstone team and project selection process for students and supervisors.
Currently it is fragmented on Teams, MS Forms for supervisors, email for supervisor communication, etc.
This creates frustration and lack of transparency.
Project descriptions vary widely in accuracy and detail, so students struggle to compare opportunities.
We saw this first hand, the system described in the project description was not fully representative of what the supervisor actually wanted us to work on.
Students have limited visibility into which projects are still available and which teams are still looking for members.
There's no unified way to track a project's status (open, filled, in progress) from submission through team assignment
This creates wasted time, mismatched teams, and administrative overhead for course coordinators and TAs

If this platform allowed you to see who else is interested in a project, it might be easier to form teams and find teammates with similar interests.

\subsection{Inputs and Outputs}

\wss{Characterize the problem in terms of ``high level'' inputs and outputs.  
Use abstraction so that you can avoid details.}

Inputs:
- Project proposals/descriptions submitted by supervisors
- Student profiles
- Student expressions of interest / applications to projects
- Administrative decisions (approvals, status changes etc.)
Outputs:
- Searchable/filterable catalog of available projects
- project status and availability information
- confirmed project-team assignments

\subsection{Stakeholders}

- Capstone Students (primary users, browse/apply to projects, form teams)

- Capstone Project Supervisors - can be professors or industry sponsors (submit and manage project proposals)

- Capstone Course Coordinator (oversees process, needs visibility/control)

- Capstone Course TAs (support administration of the process)

\subsection{Environment}

\wss{Hardware and Software Environment for the users.  The developer environment
is summarized as part of the developer plan.}

Software - the application can be accessed through any modern web browser. The application is designed to be compatible with Windows, macOS, and Linux operating systems. It requires an internet connection for full functionality.
Hardware - The application is designed to run on standard desktop and laptop computers, as well as tablets and smartphones. It does not require any specialized hardware.

\section{Goals}

- Provide supervisors/sponsors a standardized way to submit clear, complete project descriptions
- Reduce administrative overhead/manual tracking (e.g., spreadsheets, emails) currently required to manage the process
- Improve transparency so all stakeholders can see project availability and progress at any time
